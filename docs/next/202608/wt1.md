## 1. 구조

파이프라인은 두 단계, 그 사이는 JSON 하나.

```
scan.py  ──> tree.json ──> render.py ──> sprawl.html
(os.stat만)              (템플릿에 JSON 주입)
```

두 단계를 분리하는 이유는 확장성이 아니라 **디버깅** 때문이다. 도시가 이상하게 보일 때
스캔이 틀렸는지 렌더가 틀렸는지를 JSON만 열어보면 갈린다.

파일은 셋. `scan.py`, `render.py`, `template.html`. 더 늘리지 않는다.

### tree.json 스키마

```json
{
  "name": "dump1",
  "type": "dir",
  "children": [
    { "name": "DIRECTION.md", "type": "file", "size": 4364, "mtime": 1756...  }
  ]
}
```

폴더는 `size`/`mtime`을 갖지 않는다. 필요하면 렌더에서 자식을 합산한다.
스키마에 필드를 추가하려면 "도시의 규칙" 표에 자리가 있는지부터 확인한다.

## 2. 단계별 작업

### 1단계 — 스캔

`os.walk` + `os.stat`으로 트리를 만들어 JSON으로 뱉는다. 내용은 열지 않는다.

- 제외: `.git`. 그 외 `node_modules` 포함 **아무것도 제외하지 않는다**
  (DIRECTION.md: 마천루는 버그가 아니라 기능).
- 심볼릭 링크는 따라가지 않는다 (순환 방지).
- `stat` 실패(권한 등)는 해당 항목을 건너뛰고 계속한다.

> 검증: 이 레포에 돌려서 `DIRECTION.md`의 size가 `ls -l` 값과 일치.
> 심링크 순환을 만든 임시 폴더에서 무한루프 없이 종료.

### 2단계 — 배치

JSON 트리를 2D 평면 좌표로 낮춘다. 여기가 이 프로젝트에서 유일하게 어려운 부분이다.

- squarified treemap으로 폴더를 사각 구역으로 자른다.
- 구역 안쪽에 여백(거리)을 남기고 그 안에 파일 건물을 배치한다.
- 높이 = `size`를 로그 스케일. 선형이면 `node_modules` 하나가 나머지를 0층으로 만든다.
  로그 밑과 배율은 **상수로 빼서 눈으로 보고 조정한다** — 계산으로 맞출 수 없는 값이다.

> 검증: 이 레포와 `node_modules`가 큰 레포 각각에 대해, 건물이 서로 겹치지 않고
> 구역 경계를 넘지 않는다 (겹침 검사 assert).

### 3단계 — 렌더

three.js로 박스를 세우고 1인칭으로 날아다닌다.

- 건물 = 박스 하나. 창문은 텍스처가 아니라 emissive + 격자 패턴 셰이더.
- 창문 밝기 = mtime을 최근성으로 정규화. **이게 주인공이므로 여기에 시간을 제일 많이 쓴다.**
- 카메라는 fly 컨트롤(WASD + 마우스). orbit이 아니라 fly인 이유는 "도시 위를 난다"가
  DIRECTION.md의 문구이기 때문.

> 검증: 방금 수정한 파일의 건물이 육안으로 가장 밝다. 1년 전 파일은 어둡다.

### 4단계 — 분위기

여기서 타협하면 느린 `tree`가 된다. 별도 단계로 둔 이유가 그것이다.

- 비 오는 밤: 안개, 블룸(UnrealBloomPass), 젖은 바닥 반사.
- 낮 모드 없음. 토글 없음.

> 검증: 완성 기준 1번 — 내 프로젝트를 넣고 스크린샷을 찍어 보내고 싶은가. 아니면 4단계로 돌아간다.

### 5단계 — 자체 완결 HTML

`template.html`에 JSON과 JS를 문자열로 박아 단일 파일로 출력한다.

> 검증: 출력 HTML을 다른 폴더로 옮겨 더블클릭 → 그대로 뜬다.

## 3. 지금 결정해야 하는 것

**three.js를 인라인할 것인가, CDN으로 링크할 것인가.**

DIRECTION.md는 "파일 하나 던져주면 받는 사람이 더블클릭해서 그대로 볼 수 있어야 한다"고 썼다.
CDN을 쓰면 오프라인에서 흰 화면이 된다. 인라인하면 출력이 ~600KB 늘어난다.

제안: **인라인.** "던져주면 열린다"는 이 프로젝트의 배포 방식 그 자체이고, 600KB는
요즘 이미지 한 장보다 작다. 다르게 가고 싶으면 말해달라.

## 4. 하지 않기로 한 것 (재확인)

구현 중에 가장 손이 가는 순서대로:

1. import 파싱 — 선을 긋는 순간 다른 프로젝트가 된다.
2. 파일 확장자별 색상 — 내용을 안 읽는다는 원칙의 회색지대. **일단 넣지 않는다.**
   전부 같은 네온 팔레트로 가고, 도시가 단조로우면 그때 다시 논의한다.
3. 검색·필터 UI — 실용성 흉내.
4. 설정 파일 — 상수는 소스에 둔다.
